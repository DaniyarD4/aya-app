# Функционал

## Модуль 1 — Rhythm (бытовая рутина)

### Ядро модуля: движок повторяющихся напоминаний
Не банальный «таймер». Нужно несколько типов триггеров, потому что бытовые дела повторяются по-разному:
- **Фиксированный интервал** — «раз в 2 недели» (лекарства), «каждый день в 9:00» (витамины).
- **По расписанию недели** — «пн/ср/пт — спортзал».
- **Плавающий, зависящий от подтверждения** — «помыть посуду» напоминается не по часам, а через N часов после последнего приёма пищи / после того как отмечено «готовил(а) еду».
- **Сезонный/контекстный** — триггер по календарной дате + прогнозу погоды: «похолодало → проверь тёплые вещи», «через 2 недели зима → шины/одежда/обогрев».
- **Предиктивный** (позже, не MVP) — на основе истории покупок предсказывать, когда закончится товар (зубная паста, лекарства) без ручного ввода интервала.

### Ключевые сценарии
- Список покупок: ассистент сам напоминает, что пора купить X (по интервалу или предиктивно).
- Готовка еды: напоминание в привычное время, с возможностью «отложить на 1 час» / «сегодня не буду».
- Посуда: напоминание после готовки/еды, не по расписанию, а по событию.
- Лекарства раз в 2 недели: жёсткое напоминание (не дать забыть — это про здоровье, тут допустим более настойчивый тон).
- Витамины по расписанию: ежедневное, с streak (сколько дней подряд не пропущено) — но streak тут мотивационный, не карающий.
- Спортзал: напоминание + мягкий стрик, без вины за пропуск.
- Сезонная подготовка: чек-лист, который генерируется заранее (за 2-3 недели до климатического сдвига), с пунктами, которые можно отмечать.

### Требования к UX
- Напоминание = 1 тап, чтобы отметить «сделано» / «отложить» / «пропустить сегодня».
- Никаких «вы пропустили 5 раз подряд, вам должно быть стыдно» — максимум нейтральная статистика по запросу пользователя, никогда не навязанная.
- Дайджест, а не поток: несколько напоминаний дня объединяются в утренний/вечерний обзор + важные (лекарства) — отдельно и точно вовремя.

## Модуль 2 — Flow (финансовая осознанность)

### Философия (принципиально)
**Никаких блокировок трат, лимитов, «нельзя».** Цель — не сократить расходы, а сделать пользователя **осознанным** в моменте траты, через положительное подкрепление, а не вину.

### Механики
- **Логирование трат** — быстрое, 1-2 тапа (сумма + категория, сумма может подтягиваться из push от банка/SMS в будущем — не MVP).
- **Осознанность вместо запрета**: при трате приложение не спрашивает «точно хочешь это купить?» (это уже похоже на запрет-в-мягкой-обёртке). Вместо этого — **пост-фактум мягкая рефлексия по желанию пользователя**: «это была спонтанная радость или запланированная?» — без осуждения ни за один из вариантов, оба варианта дают награду за сам факт осознанного ответа.
- **Квесты** — короткие, необязательные: «отметь траты за сегодня», «раз в неделю посмотри итог месяца», «отложи любую сумму в цель» — выполнение = награда.
- **Награды** — дофаминовый контур, но без «казино»-эстетики (никаких колёс фортуны, лутбоксов). Award за **факт вовлечённости** (логирование, рефлексию, стрик пользования), не за «не потратил». Примеры: очки/уровни, косметика приложения (темы, значки), позже — что-то материальное по выбору самого пользователя (это его решение, не системы).
- **Финансовая грамотность** — короткие необязательные карточки/квизы («что такое сложный процент», «эмоциональные покупки — это нормально, вот как их замечать»), не лекции, без назидательности.
- **Цели** — пользователь сам задаёт (например, накопить на что-то), приложение не создаёт цели по умолчанию и не оценивает прогресс негативно.

### Явно НЕ делать
- Не блокировать/предупреждать о превышении бюджета.
- Не показывать «сколько вы могли бы сэкономить, если бы не купили кофе X раз».
- Не сравнивать с другими пользователями (соревновательный стыд).
- Не использовать негативные пуши («вы забыли записать траты 3 дня»).

## Модуль 3 — Ассистент-персона (голос, языки)

- Female voice persona, тёплый/дружелюбный тон, не «корпоративный робот».
- 3 языка: казахский, русский, английский — с возможностью переключения и авто-определением по устройству/явному выбору.
- Голосовой ввод (сказать «отметил(а) лекарства») и голосовой вывод напоминаний как опция, не единственный канал (текст/пуш — всегда fallback).
- Тон общения — friendly, non-judgmental, ближе к «подруга-помощница», чем к ассистенту-функции. Совпадает с принципом «ноль запретов и вины» из Flow.
- ⚠️ Технический риск: качество TTS/STT для казахского языка ограничено у большинства провайдеров — нужен отдельный этап research (см. [05-risks-open-questions.md](05-risks-open-questions.md)).

## Модуль 4 — Носимые устройства (будущее, не MVP)

- Apple Watch (HealthKit) — естественная точка входа на iOS: шаги/активность → умные напоминания про спортзал, сон → более мягкий тон утренних напоминаний при недосыпе.
- Смарт-браслеты сторонних брендов (Xiaomi/Huawei и т.п.) — через их SDK/открытые API, отдельная интеграция позже.
- Ключевая идея: браслет не диктует запреты («не ешь») — только контекст для более уместного тайминга напоминаний.

## Модуль 5 — Экосистема (горизонт 2+)

- Общее ядро (аккаунт, напоминания, уведомления, ассистент-движок) + подключаемые модули (Rhythm, Flow, Health, позже — Shopping/Delivery, Family).
- Семейный шеринг списков/напоминаний (например, общий список покупок на семью) — заложить как возможность в архитектуре, не строить в MVP.
- Сторонние интеграции: доставка продуктов, аптеки (авто-заказ лекарств вместо просто напоминания).
